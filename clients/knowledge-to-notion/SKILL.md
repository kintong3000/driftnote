# 上下文 → 知识总结 → Notion

目标：把这次对话里**值得长期保留的知识**整理成一篇半年后的自己（或不了解背景的同事）也能直接看懂、拿来用的笔记，然后存进 Notion。

用户的附加要求：$ARGUMENTS
（如果写了主题，就只总结和这个主题相关的部分；写了类型就传给 `--type`。）

## 第一步：提炼（先想清楚再写）

把上下文过一遍，分成三类：

- **保留**：结论、原理/原因（为什么这样）、做出的决定及取舍、可复用的步骤/命令/代码、踩过的坑和解决方法、仍未解决的问题、有价值的参考链接。
- **压缩**：试错过程。失败的尝试只留下「试了什么 → 为什么不行」这条教训，一两句话即可。
- **丢弃**：寒暄、重复确认、工具调用的原始输出、已被推翻且没有教训价值的中间想法、和主题无关的支线。

## 第二步：按模板写

使用下面的结构，**没有内容的章节直接删掉**，不要写「无」。章节可以按内容改名或合并。

```markdown
# <具体的标题：说清是什么问题/什么知识，不要用「对话总结」这类空标题>

> **一句话结论**：<最核心的结论或收获>

## 背景
<要解决什么问题、在什么环境/约束下。2–4 句>

## 核心知识
<概念、原理、机制。每点写清「是什么 + 为什么」，用小标题或列表组织>

## 决策与取舍
- **选择了 X 而不是 Y**：原因……

## 操作步骤 / 关键代码
<只留可直接复用的最小片段，代码块标注语言>

## 踩坑与注意事项
- **现象** → 原因 → 解决办法

## 待解决 / 后续
- [ ] ……

## 参考
- [名称](链接)
```

### 详略的尺度

「不要太简洁，也不要太冗余」的具体标准：

- **自包含**：每个要点脱离上下文也能看懂。不写「上面那个方法」「刚才的报错」，要写出具体名字、具体报错信息、具体版本。
- **保留理由**：结论后面带上「因为……」。只有结论没有原因的笔记过几个月就没法判断还适不适用。
- **不复述过程**：写「是什么、为什么、怎么做」，不写「我们先……然后……接着……」的流水账。
- **一点一事**：每条列表一个信息点，通常 1–3 行；需要更多解释时用小标题 + 段落。
- **代码克制**：只放关键片段和命令，不粘贴整个文件；长输出只摘关键行。
- **篇幅随内容走**：一般 300–1500 字。简单问题宁可短，内容丰富的长对话也别超过 ~2500 字——超过时考虑按主题拆成多篇（分别保存）。
- **语言**：跟随对话的主要语言；术语、命令、标识符保持原文。

### 写完自检

- [ ] 标题能让人在搜索结果里一眼认出这篇是什么
- [ ] 一句话结论单独拿出来也成立
- [ ] 没有指代不明的「这个」「上面」
- [ ] 关键决策都写了原因
- [ ] 删掉任何一节都会丢失有用信息（否则就删）
- [ ] 没有密钥、token、密码、个人隐私等敏感信息（有就打码或删除）

## 第三步：保存到 Notion

通过 driftnote 的 `/api/capture` 保存，环境变量和终端命令 `note` 共用（`NOTE_ENDPOINT`、`NOTE_TOKEN`、`NOTE_SOURCE`）。

1. 用 Write 工具把总结写入一个临时 `.md` 文件（放在临时目录/scratchpad，不要放进用户项目）。
2. 执行：

```bash
python3 ~/.claude/skills/knowledge-to-notion/scripts/save_to_notion.py /path/to/summary.md
```

- 标题自动取正文第一行的 `# 标题`（并从正文中移除），也可以用 `--title` 覆盖。driftnote 只保留标题前 60 个字，所以标题要短。
- 「内容」属性会填入正文里第一段 `>` 引用（一句话结论），完整总结按 Markdown 渲染进页面正文的「知识总结」一节。
- 类型默认 `AI对话`；纯技术知识可以用 `--type 技术`（必须是 driftnote `TYPES` 里的值）。
- 标签不用传，由 driftnote 夜间 AI 统一打。

3. 成功后把脚本输出的 Notion 链接告诉用户，并附上 2–3 行总结要点。保存后删除临时文件。

### 出错时

- `未设置 NOTE_ENDPOINT / NOTE_TOKEN`：告诉用户按下面的方法配置，同时把总结的 Markdown 原文给用户，免得内容丢失。
- `401`：密钥不对，`NOTE_TOKEN` 应该和 Worker 的 `AUTH_TOKEN` 一致。
- 网络错误或服务端 5xx：脚本已把请求存进 `~/.note_failed.jsonl`，告诉用户稍后运行 `note-retry` 重发即可（带同一个 id，不会重复写入）。

## 配置

和 `note` 命令共用，已经配好 `note` 的话不需要再配置：

```bash
# ~/.zshrc
export NOTE_ENDPOINT="https://driftnote.<你的子域>.workers.dev"
export NOTE_TOKEN="<与 Worker 的 AUTH_TOKEN 相同>"
# export NOTE_SOURCE=claude-code   # 可选，默认就是 claude-code
```

检查：`python3 ~/.claude/skills/knowledge-to-notion/scripts/save_to_notion.py --check`
